1 什么是超网直觉

普通 NAS 把每个候选架构当作一个独立模型：训练一次、评估一次、丢掉。N 个候选就是 N 次训练。

超网（supernet）是把所有候选架构的并集放进同一套权重里。所有可能的层都在，权重按“最宽的那个子网”分配；任意一个子网都不是新模型，而是这份共享权重的切片——深度取前 L 层、宽度取前 d 个通道、每个 block 从 FFN 分支里挑一支。

朴素 NAS                         超网（one-shot）
候选 A ─ 训练 ─ 评估 ─ 丢弃         ┌───────────── 共享权重池 ─────────────┐
候选 B ─ 训练 ─ 评估 ─ 丢弃   ⟶     │ depth 4..10 · width 64/96/128        │
候选 C ─ 训练 ─ 评估 ─ 丢弃         │ 每层 9 个 FFN 分支 · 激活 gelu/silu   │
...  N 次训练                       └──────────────────────────────────────┘
                                     子网 = 切片 → 一次训练，N 个子网可评估

这次的任务

MNIST 手写数字分类：一张 28×28 的图被看成 28 个 token （每行一个 token，每行的 28 个像素值就是它的特征）， 过完超网后做平均池化，再输出 10 类 logits。 随机猜的准确率是 10%，好坏一眼就能看懂。

本仓库这次覆盖了多大的空间？

空间里有 22,682,968,226,208 个不同的候选架构（深度 4–10 × 宽度 × 每层 FFN 分支 × 激活）， 但训练只发生在一份 18.42M 参数的权重上。这就是权重共享省下来的东西。

关键区别：超网省的是“训练”，不省“测量”。延迟 / FLOPs 这类目标仍然要单独测，或查表。

每一层那三个字段到底是什么意思

逐层可搜索的只有三项，其余都是全局或写死的。一个 block 的实际计算是：

x = x + Attention( LayerNorm(x) )                       ← 宽度 / head 数来自全局 embed_dim、head_dim
x = x + conv1d_k( LayerNorm(x) , out = dim x ratio )    ← kernel、ratio 来自这一层
        -> activation(...) -> conv1d_1( out = dim )
字段取值含义落到模型上
ffn_ratio2 / 3 / 4FFN 隐藏层宽度倍数：hidden = embed_dim x ratio选哪条分支；分支容量按 max_dim x ratio 分配，再切前 dim x ratio 个通道
ffn_kernel1 / 3 / 5FFN 第一个 Conv1d 的卷积核大小k=1 只看当前 token；k=3 / 5 会把相邻 token（本任务是相邻图像行）卷进来
activationgelu / siluFFN 里的激活函数无参数，运行时按名字切换函数
（全局）embed_dim / head_dim见上表宽度与 head 大小，所有层共用head 数 = embed_dim / head_dim；注意力输出投影取左上块
（全局）depth4–10只跑前 L 层截断，不复制权重
记账坑：arch_id 只对“可搜索变量”做哈希。 arch_id 覆盖 depth / embed_dim / head_dim / layers 四项。 如果你改了写死的部分（池化方式、归一化类型、注意力是否遮挡、位置编码）， arch_id 一个字符都不会变，但模型已经不是同一个了。 所以实验记录必须把 arch_id 和空间定义 （space.to_dict()）成对保存——本仓库的 metrics.json 就是这么存的。
为什么 FFN 用“分支”而宽度用“切片”？ 切片只在“同一组权重的前缀”有意义时才等价于一个真实的窄模型。 通道维度可以取前缀（前 d 个通道），卷积核大小不行——k=5 的卷积核没有“前 3 个”这种子结构，所以 kernel 只能并列存放、整支激活。

3 权重共享与切片核心技巧

切片只发生在 forward 里几行：权重按最大宽度分配，子网取前 out_channels × in_channels 那块。同一份参数因此同时服务宽子网和窄子网。

supernet/modules.py · snippet elastic-conv
def forward(self, x: Tensor, out_channels: int, in_channels: int) -> Tensor:
    if out_channels > self.max_out_channels:
        raise ValueError(
            f"out_channels {out_channels} exceeds capacity {self.max_out_channels}"
        )
    if in_channels > self.max_in_channels:
        raise ValueError(
            f"in_channels {in_channels} exceeds capacity {self.max_in_channels}"
        )
    if x.shape[1] != in_channels:
        raise ValueError(
            f"input has {x.shape[1]} channels but subnet needs {in_channels}"
        )
    weight = self.weight[:out_channels, :in_channels]
    bias = None if self.bias is None else self.bias[:out_channels]
    return F.conv1d(x, weight, bias, padding=self.padding)

FFN 的分支选择同样只是一个字典查找：

supernet/modules.py · snippet elastic-ffn
def forward(
    self, x: Tensor, dim: int, ffn_ratio: int, ffn_kernel: int, activation: str
) -> Tensor:
    key = branch_key(ffn_ratio, ffn_kernel)
    if key not in self.branches:
        raise KeyError(f"branch {key} not instantiated; have {list(self.branches)}")
    return self.branches[key](x, dim, activation)

整网前向就变成“截断深度 + 一路切片”：

supernet/supernet.py · snippet supernet-forward
def forward(self, inputs: Tensor, spec: SubnetSpec) -> Tensor:
    """Run one subnet over a batch; returns class logits (batch, num_classes)."""
    spec.validate(self.space)
    if inputs.dim() != 3:
        raise ValueError("inputs must be (batch, input_features, seq_len)")
    features, seq = inputs.shape[1], inputs.shape[2]
    if features != self.space.input_features:
        raise ValueError(
            f"input has {features} features but the space expects "
            f"{self.space.input_features}"
        )
    if seq > self.space.max_seq_len:
        raise ValueError(f"seq {seq} exceeds max_seq_len {self.space.max_seq_len}")
    dim = spec.embed_dim
    x = self.input_proj(inputs, dim, features) + self.pos[:, :dim, :seq]
    for index in range(spec.depth):
        layer = spec.layers[index]
        x = self.layers[index](
            x,
            dim,
            spec.head_dim,
            layer.ffn_ratio,
            layer.ffn_kernel,
            layer.activation,
        )
    x = self.norm(x, dim)
    pooled = x.mean(dim=-1, keepdim=True)
    return self.head(pooled, self.space.num_classes, dim).squeeze(-1)

注意力也一起变窄

宽度不只影响 FFN。qkv 卷积的输出通道按 3 x max_dim 分配，窄子网只取前 3 x dim 行； 这 3 x dim 行按 (q, k, v) 三段切开后，每段恰好是“前 heads 个 head”，所以 head 数是 dim / head_dim 自然跟着宽度变。输出投影则取左上 dim x dim 的块。

这就是为什么 head_dim 也要放进搜索空间：固定宽度下，head_dim 小意味着更多 head（更细的注意力）， 但每个 head 的维度更小。两者都受同一份共享权重的切片约束。

这是近似，不是等价。 取“前 d 个通道”得到的窄卷积，参数值继承自宽子网，但没有单独训练过； 导出子网上线前需要 fine-tune。另外，本仓库用 LayerNorm，所以导出时不需要重估统计量；如果换成 BatchNorm， 必须用一批数据重新校准 BN（BN re-estimation），否则精度会明显掉。

4 三明治规则训练规则

随机采样一条路径有个毛病：大子网和小子网都很少被连续训练，权重会朝“随机平均”跑偏。三明治规则每步固定训练四类子网：

  1. max：最贵子网（depth 10 / width 128 / ratio 4 / kernel 5）——质量上限，也是其他子网的“教师”；
  2. min：最便宜子网（depth 4 / width 64 / ratio 2 / kernel 1）——保证低端不掉队；
  3. random × 2：均匀采样，负责覆盖中间地带。

四条腿的损失求和后只做一次 optimizer step，所以步数预算的口径是“4 个子网 / 步”。

supernet/sandwich.py · snippet sandwich-build
def build_sandwich(self) -> list[tuple[str, SubnetSpec, float]]:
    """Return the (role, spec, loss_weight) legs of this step's sandwich."""
    config = self.config
    legs: list[tuple[str, SubnetSpec, float]] = [
        ("max", self.space.max_subnet(), config.max_weight),
        ("min", self.space.min_subnet(), config.min_weight),
    ]
    for index in range(config.n_random):
        legs.append(
            (f"random_{index}", self.space.sample(self.rng), config.random_weight)
        )
    return legs
supernet/sandwich.py · snippet sandwich-step
def train_step(self, inputs: Tensor, labels: Tensor) -> StepRecord:
    self.model.train()
    self.optimizer.zero_grad(set_to_none=True)
    role_losses: dict[str, float] = {}
    role_accuracy: dict[str, float] = {}
    role_arch_ids: dict[str, str] = {}
    total = 0.0
    for role, spec, weight in self.build_sandwich():
        logits = self.model(inputs, spec)
        loss = classification_loss(logits, labels)
        if weight > 0:
            (loss * weight).backward()
        role_losses[role] = float(loss.detach())
        role_accuracy[role] = accuracy(logits.detach(), labels)
        role_arch_ids[role] = spec.arch_id
        total += weight * float(loss.detach())
        self.stats.record(spec)
    grad_norm = torch.nn.utils.clip_grad_norm_(
        self.model.parameters(), self.config.grad_clip
    )
    self.optimizer.step()
    self.step_index += 1
    self.stats.steps = self.step_index
    return StepRecord(
        step=self.step_index,
        total_loss=total,
        grad_norm=float(grad_norm),
        role_losses=role_losses,
        role_accuracy=role_accuracy,
        role_arch_ids=role_arch_ids,
    )

5 一次训练得到一个子网族收益

训练结束后，同一份权重里可以取出任意多的子网并立刻打分。下面是没有额外训练的两次扫描：固定最大宽度扫深度 4→10，固定最大深度扫宽度。

这两条曲线怎么读

  • 曲线为什么几乎平？ 本次 depth 从 4 加到 10， 准确率只动了不到 1 个点——说明这个任务在当前训练量下深度已经饱和， 而不是“深度没用”。判断依据：更深的子网更容易欠训（见第 4 节覆盖图，depth 10 只在 max 腿每步出现）。
  • 为什么宽度更有效？ 宽度直接影响每层的通道数，也影响 head 数；同样的训练步数下， 宽子网拿到的梯度更多（每次更新的参数更多），所以低宽度端掉得更快。
  • 右图怎么用？ 每一点都是一个“可直接部署”的配置：横轴是成本（参数量），纵轴是质量。 选模型就是在左上角找点——这就是超网真正交付的东西：一条成本-质量曲线，而不是一个架构。
  • 注意非单调。 宽度扫描里更宽的子网偶尔更差（本次 w96 就低于 w64）， 这不是 bug，而是“训练不均衡 + 评测噪声”的体现，值得让学生自己找反例。

6 陷阱：排序不一致必读

超网内损失低，不等于独立训练后也好。共享权重是在“邻居分支也在被训练”的前提下学出来的（co-adaptation），所以两套排序可能对不上。本次实验直接量了这件事：抽 10 个候选，先用超网打分， 再把每个候选从零独立训练同样步数后打分。

τ 不够用：搜索真正关心的是 recall@k

τ 衡量全序是否一致，而搜索只关心一件事：真实最好的几个子网，有没有被超网排进前 k 名。 这两个指标可以不一致，所以两份都该报。

指标本次实测随机基线
recall@10/10.10
recall@31/30.30
recall@53/50.50

如果 recall@k 和随机基线差不多，那就不能拿超网当筛选器——本次正处在边缘： recall@1 为 0，recall@3 与基线持平。用法判断标准：τ > 0.7 可当可靠代理； 0.3–0.7 只能粗筛且必须复核；τ < 0.3 基本无效（阈值任务相关，需自己量）。

教学要点：τ 只有 0.33，说明“超网最优”这个结论并不天然可信。 样本量小（10 个候选）时 τ 的置信区间很宽，所以上面的数字只用于演示方法，不作为结论。

那超网还能用吗？三种安全用法

  1. 只当粗筛：超网从几千个候选里选前 20，再用独立训练重排。省的是粗筛的钱。
  2. 当加速器而非论文主张：主实验的预算口径仍然按“独立训练次数”记，超网只出现在附录。
  3. 把它当作被研究的对象：把“超网内排序与真实排序的相关性”本身做成一个可报告的量（就是本页第 6 节）。

7 预算记账：把超网纳入实验口径方法学

一旦换了评估器，不同策略的候选就不再是在同一把尺子下比较。下表是接入任何 NAS/HPO 对比时必须写清的量：

成本是极不对称的：超网侧打分 = 一次前向 + 一批候选，几乎免费；真值侧 = 每个候选一次完整训练。 所以扩大审计规模（更多候选 / 更多种子）的代价是线性上涨的：把候选从 10 提到 30、 再跑 3 个种子，审计开销就会超过训练超网本身。这也是为什么很多 one-shot 论文只报最终架构精度、不报排序一致性—— 不是不重要，是很少给得起这个预算。

原则：超网内损失只能用于筛选，不能用于报告。任何“我们的方法更好”的结论，最后的数字必须来自固定评估器下的独立训练。

两次消融的实测结果

这不是本页那一次运行的数字，而是另外跑的两次（同机、同评估口径：同一批测试图，每个候选独立训练 120–150 步），每次只改一个设置：

配置训练步数max 子网min 子网随机子网宽度 w64 / w96Kendall τ
完整三明治（本页那次）182698.1%96.9%93.0%95.8% / 92.8%+0.33
只留 max + min（--n-random 0）60092.5%95.2%20.8%48.8% / 44.7%+0.20
训练量砍到 200 步（--steps 200）20084.8%77.7%60.2%72.0% / 76.1%-0.20

看中间那一行：去掉随机腿之后，两端依然健康（max 92.5%、min 95.2%），但中间地带塌了—— 宽度 w64/w96 从 95.8%/92.8% 掉到 48.8%/44.7%，随机采样子网从 93.0% 掉到 20.8%。 所以三明治的三条腿各管一段：max 管上限、min 管下限、随机腿管中间地带，缺哪条就塌哪段。

最后一行则说明另一件事：训练量不足时，不只是精度低，连排序都会从正相关翻成负相关（τ +0.33 → -0.20）。 τ 不是超网的固有属性，而是“超网 + 训练量”的属性。

建议的第一次实验：把 --steps 从默认值砍到 200， 再对比第 6 节的 τ / recall@k。你会看到“超网内排序”从“勉强可用”变成“完全不可用”—— 这比任何文字都更能说明：超网分数是代理，不是结论。
