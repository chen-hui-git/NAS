# 导出子网的微调（fine-tune）配方与实测收益

## 为什么需要微调

超网里的子网是**切片**，不是独立训练过的模型：

- 窄子网用的是宽子网权重的**前 d 个通道**，这些通道是在"宽子网也参与训练"的前提下学出来的；
- 每一层选的分支只被**边际覆盖**过（本仓库 joint 训练里每个 `(层, ratio-kernel)` 组合约 555 次），
  而"这一整套组合"几乎没有被整体训练过。

所以超网内分数**天然偏乐观或偏悲观**，导出后单独再训几百步就能把这个具体形状调到最好。

## 三行核心代码（仓库里已有封装）

```python
model = supernet.export_subnet(spec)                      # 切片拷贝成独立模型（不碰超网）
model = fine_tune_subnet(supernet, spec, task,            # supernet/rank.py
                         steps=150, lr=3e-4, batch_size=128)
accuracy = subnet_accuracy(model, spec, eval_batches)     # 打分
```

要点：

| 选择 | 值 | 理由 |
| --- | --- | --- |
| 起点 | `export_subnet(spec)` | 权重直接继承超网切片，**zero-shot 分数 = 超网内分数**（有测试保证逐位一致） |
| 学习率 | `3e-4`（预训练的 1/10） | 权重已经训过，大 lr 会把已学好的结构打散 |
| 步数 | 150–400 | 实测 150 步已拿到大部分收益，400 步接近饱和 |
| 是否影响超网 | **不影响** | `export_subnet` 是拷贝，微调只改副本 |

## 实测收益（用本仓库默认配置训出的超网：KD λ=0.5、1249 步、batch 128）

| 子网 | 参数量 | zero-shot（超网内） | 微调 150 步 | 微调 400 步 | 收益 |
| --- | --- | --- | --- | --- | --- |
| **max** d10/w128/r4k5 | 4.61M | 99.12% | 99.22% | **99.51%** | **+0.39** |
| **min** d4/w64/r2k1 | 0.14M | 96.68% | 98.05% | **98.34%** | **+1.66** |
| **随机采样** | 0.31M | 94.92% | 98.34% | **98.63%** | **+3.71** |

复现方式：`run_demo.py --save-weights` 存下 `report/supernet.pt`，再加载它做上面三行。

### 关键规律：越欠训的子网，微调收益越大

| 子网 | 免蒸馏超网上的收益（另一次对照） | 带 KD 超网上的收益（上表） |
| --- | --- | --- |
| max | +1.9 | **+0.39** |
| min | +5.8 | **+1.66** |
| 随机 | +12.4 | **+3.71** |

两列一起看有两个信息：

1. **收益随子网欠训程度单调上升**：随机 > min > max；
2. **KD 已经把一部分"欠训"补掉了**，所以微调的剩余空间缩小——这正是蒸馏与微调互为替代的证据。
   换句话说：**先上 KD，再考虑微调**，性价比更高。

## 什么时候需要微调

| 场景 | 需要吗 |
| --- | --- |
| 只做原理演示或报告超网内相对排序 | 不需要 |
| 要交付某个具体子网到生产（尤其小模型） | 需要，150–400 步成本极低 |
| 想把"超网 + 微调"当作搜索的最终结果 | 需要，但**必须与"独立训练"基准分开报** |
| 想用微调后精度替代排序审计的真值 | **不行**——那会变成混合口径（见下） |

## 三个坑

1. **不要把微调后的精度当成"独立训练基准"**。`rank.py` 里的真值是 `train_standalone`
   （**随机初始化**、从零训练同样图片预算）。微调是"超网 + 少量训练"，口径不同，混用会让 τ 失真。
2. **微调会改变排序**。多个子网各自微调后，彼此顺序可能与超网内顺序不同；要报排序就统一口径。
3. **权重必须落盘才能事后微调**。默认不保存（74 MB），需要 `--save-weights`：

```bash
PYTHONPATH=. python3 examples/run_demo.py --save-weights     # 写 report/supernet.pt
```

恢复方式：

```python
supernet = Supernet(space)
supernet.load_state_dict(torch.load("report/supernet.pt", map_location="cpu"))
```

`space` 可以从同一份 `metrics.json` 的 `run.space` 重建（字段一一对应），
这样 checkpoint 与空间定义永远配套，不会出现"权重对上了但空间变了"的错配。

## 成本

在 M5 Pro + MPS + batch 128 上，单条腿约 30–45 ms/步，所以：

| 子网数 | 步数 | 大致耗时 |
| --- | --- | --- |
| 3 | 150 | ~15–20 s |
| 3 | 400 | ~40–55 s |
| 10 | 150 | ~50–70 s |

比排序审计便宜得多（审计是每个候选从零训 125 步，但需要 10 个候选）。
