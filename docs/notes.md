# 开放问题与常见误区

这份文档记录本仓库实践中反复被问到的三个问题、它们的答案（都带实测数字），以及几个容易搞错的地方。
所有数字来自 `report/metrics.json` 与 `docs/comparison.md` / `docs/finetune.md` 里的运行。

---

## 问题 1：最小子网的损失，一定会高于最大子网吗？

**不一定。** 超网里的 min 子网不是 max 子网的严格子集：它用的是同一份权重的**前缀切片**
（前 4 层、前 64 个通道、k=1 的卷积核），缺的那部分参数不是"学着不用"，而是根本不存在。
所以"容量小 ⇒ 损失大"只是**统计倾向**，不是必然。

**实测反例（同一次运行、同一批测试图）：**

| 对比 | 结果 |
| --- | --- |
| max 子网 d10/w128/r4·k5（4.61M） | loss 0.062 / acc 97.7% |
| min 子网 d4/w64/r2·k1（0.14M） | loss 0.137 / acc 95.7% |
| **随机子网（0.39M，是 min 的 2.8 倍参数）** | **94.1% —— 比 0.14M 的 min 子网更差** |
| **深度扫描 d9 vs d10** | 都是 97.7%（更深没有更好） |
| 逐张预测（0–9 各一张） | max 对 9/10、min 对 8/10 —— 单张层面并不稳定 |

**"通常更差"的两个真实机制：**

1. **容量真的更小**：0.14M 参数要拟合同样的 10 类问题，上限更低；
2. **训练次数不均**：max 腿每步都训（每步 10 层 × r4k5），随机腿里的分支训练次数少得多——
   实测覆盖统计里 k=5 分支被训练约 26000 次、k=3 只有约 8300 次。

> 推论：看到 d10 不如 d9 时，正确的追问不是"深度没用"，而是"这套权重给 d10 的训练够不够"。

## 问题 2：把三明治里的 min 腿去掉，会坏在哪里？

**不是"少一份数据"，而是破坏了覆盖契约。** 三个具体后果：

1. **最低成本角点失去唯一的稳定梯度源**。空间有 2.27×10¹³ 个候选，随机腿抽中"最便宜角点"的概率约等于 0，
   min 腿是它唯一"每步必训"的保障。
2. **分支覆盖立刻失衡**。实测覆盖（按层计）：ffn_kernel 1 / 3 / 5 = 15913 / 8486 / **26642**；
   ffn_ratio 2 / 3 / 4 = 15854 / 8447 / **26740**；depth 4 / 5–9 / 10 = 2364 / 约 500 每档 / 2359。
   最小值侧（k=1、r2、depth 4）几乎全靠 min 腿撑着。
3. **少了 in-place distillation 的一极**。四条腿共享权重、互为教师；砍掉一端，参数就只朝大子网饱和，
   窄子网的前缀切片会退化成"用不到的通道"。

**直接证据**：一次运行里随机采到的 d10/w128 子网（每层分支随机）在超网内只有 88.3%，
而训练充分的 max 角点（全 r4k5）是 98.1%——同样参数量差 10 个点，差的就是"这条分支被训练了多少次"。

## 问题 3：τ 只有 0.3 左右时，还能用超网做搜索吗？

**不能当排序用，连粗筛都要先量。** 默认配置的实测（10 个候选）：

| 指标 | 值 | 随机基线 |
| --- | --- | --- |
| Kendall τ | +0.244 | 0 |
| Spearman ρ | +0.418 | 0 |
| top-1 是否一致 | **否** | 10% |
| recall@1 | 0/1 | 0.10 |
| recall@3 | 2/3 | 0.30 |
| recall@5 | **2/5** | 0.50 |
| regret（信任超网 top-1 的代价） | 0.013 loss | — |

**判断标准：** τ > 0.7 可当可靠代理；0.3–0.7 只能粗筛且必须复核；τ < 0.3 基本无效（阈值任务相关，需自己量）。
注意 **τ 衡量全序，搜索只关心 top-k 召回**，两者可以不一致，所以该报的是 **recall@k**，不是只有 τ。

**三条使用准则：**

1. 超网分数只用于**筛选**，最终数字必须来自固定评估器下的**独立训练**；
2. 同时报 **τ、ρ、recall@k、regret**；
3. 严格分账：超网内分数与独立训练分数不许混着报（`evaluator_kind` 字段就是为此存在）。

## 常见误区

| 误区 | 纠正 |
| --- | --- |
| "min 参数少，所以损失一定更大" | 反例见上：w96 曾低于 w64、d9 曾高于 d10 |
| "去掉 min 只是少一条训练路径" | min 腿是低端分支的**唯一稳定梯度源**，去掉后 k=1/r2/depth-4 侧直接饿死 |
| "τ 低，但 top-1 刚好猜对了，所以能用" | 本次 top-1 就猜错了，recall@3 = 0/3 |
| "训练完把没用的参数剪掉" | 没有裁剪动作：切片只是取视图，参数一直在、一直被别的子网读 |
| "窄子网的权重是独立训练过的" | 它是宽子网权重的左上角，直接继承（所以导出后需要微调） |
| "超网省的是时间，所以测量也省了" | 超网只省训练；延迟 / FLOPs / 显存必须单独测 |
| "微调后的精度可以当独立训练基准" | 口径不同（超网 + 少量训练 vs 从零训练），混用会让 τ 失真 |

## 两个开关的实测结论

| 组 | 步数 | max | min | 随机子网 | Kendall τ |
| --- | --- | --- | --- | --- | --- |
| joint（关蒸馏） | 1788 | 96.9% | 96.2% | 93.0% | +0.29 |
| 渐进收缩 PS | 1326 | 95.6% | **78.0%** | **69.7%** | +0.20 |
| 子网蒸馏 KD | 1798 | **97.7%** | 96.2% | **97.0%** | +0.29 |

- **KD 几乎免费**（墙钟与步数不变，教师就是本来要算的 max 腿），所以**已设为默认 λ=0.5**；
- **PS 在小预算下是负收益**（解锁太晚 + 前段单步更贵），默认关闭；
- 两个开关都**没有改善排序一致性**——蒸馏提升的是子网质量，不是排序可用性。
